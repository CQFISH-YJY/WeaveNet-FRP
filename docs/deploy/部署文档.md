# WeaveNet 织网穿透 部署文档

> 项目：准商业级 FRP 全套程序（服务端、客户端、管理端、官网）
> 品牌：WeaveNet・织网穿透
> 文档：CQFISH&喵酱出品
> 日期：2026-08-15

本文档依据《2026-08-15-weavenet-design.md》设计文档编写，描述 WeaveNet 织网穿透（以下简称 WeaveNet）服务端的部署方式。所有端口、容器、配置与流程均以设计文档为准。

## 1. 部署架构概述

WeaveNet 采用单机 Docker Compose 编排部署，共 4 个容器，构成应用层（面板、官网）、数据层（SQLite、Redis）、穿透层（frps）与应急层（应急服务）四层结构。

### 1.1 容器拓扑

- weave-panel：FastAPI 面板 + 官网 + 静态前端，挂载 sqlite 数据卷
- weave-redis：redis:7-alpine
- weave-frps：Go 穿透服务端，暴露 7000（控制）/ 80 / 443（隧道）
- weave-emergency：应急服务，端口 9001（仅内网 / VPN 访问）

### 1.2 组件拓扑

- 用户浏览器：官网访问、面板操作、外部服务访问
- 应用层：官网（FastAPI + Jinja2）、面板 API（FastAPI）、面板前端（Vue3 静态）
- 数据层：SQLite（WAL）+ Redis（会话 / 缓存 / 实时状态）+ asyncio 后台任务
- 穿透层：frps 服务端（Go 二开，全家桶隧道类型）
- 客户端：Electron 桌面程序 + frpc（Windows 10/11）

### 1.3 数据流

1. 用户在面板创建隧道，面板写入 SQLite，隧道配置缓存到 Redis
2. frps 每 10s 轮询面板拉取本节点名下隧道与用户限速配置（热更新，无需重启）
3. Electron 客户端登录面板拉取隧道列表，生成 frpc.toml，启动 frpc 子进程
4. frpc 携带用户 Token 连接 frps，鉴权通过建立隧道
5. frps 每 30s 上报隧道在线状态、连接数、流量增量，面板入库并刷新 Redis
6. 面板心跳检测 frps，超过 60s 无心跳标记节点离线

## 2. 端口规划

- 8000：面板 + 官网（HTTPS 反代后）
- 7000：frps 控制通道
- 80 / 443：HTTP(S) 隧道
- 9001：应急服务（仅内网 / VPN）

端口说明：

- 8000 为面板与官网的监听端口，对外通过 HTTPS 反向代理访问
- 7000 为 frps 控制通道，供 frpc 客户端连接鉴权
- 80 / 443 为隧道端口，承载用户 HTTP / HTTPS 隧道流量
- 9001 为应急服务端口，仅限内网 / VPN 访问，不对外暴露

## 3. 环境要求

- 部署形态：单机部署，使用 Docker Compose 编排（4 容器）
- 目标规模：注册用户 1 万以内，在线隧道 500 以内
- 整体内存占用目标：200MB 以内
- 宿主机需具备 Docker Compose 运行环境

组件依赖：

- 面板后端：Python 3.12 + FastAPI，uvicorn 单进程
- 数据库：SQLite（WAL 模式 + busy_timeout），数据挂载于 weave-panel 数据卷
- 缓存 / 会话：轻量 Redis 单实例（镜像 redis:7-alpine）
- 异步任务：asyncio 后台任务（不引入 Celery / 消息队列）
- 面板前端：Vue3 + Naive UI，构建为静态文件
- 官网：FastAPI + Jinja2 服务端渲染
- 穿透内核：Go 服务端，基于 fatedier/frp 二次开发
- 应急服务：独立轻量进程，标准库实现，零依赖

## 4. 配置说明

### 4.1 环境变量模板

部署配置位于仓库 deploy 目录，提供 .env.example 环境变量模板，具体变量以仓库实际文件为准。部署时将模板复制为 .env，并按部署环境填写。

### 4.2 SQLite 数据卷

- weave-panel 容器挂载 sqlite 数据卷，数据库文件持久化保存在数据卷中
- SQLite 启用 WAL 模式 + busy_timeout，锁冲突时写操作重试
- 在线状态与实时流量缓存于 Redis，不入库；历史流量按日聚合写入 traffic_stats

### 4.3 Redis 配置

- 使用 redis:7-alpine 单实例
- 承担会话、缓存、实时状态三类职责
- 在线状态与实时流量存于 Redis，供面板与 frps 状态上报刷新

### 4.4 frps 配置要点

- frps 通过控制通道 API 向面板注册节点并心跳上报
- 隧道配置热拉取：每 10s 从面板拉取本节点隧道与用户套餐限速，热更新无需重启
- 客户端鉴权对接：frpc 使用面板签发的用户 Token 鉴权连接 frps
- 限速联动：按用户套餐带宽上限动态限速
- 状态上报：在线隧道、连接数、流量增量每 30s 上报
- 远程端口分配校验：防止端口冲突
- 免费域名路由：按域名将请求路由到对应隧道

## 5. 部署步骤

### 5.1 项目目录结构

Monorepo 结构，部署相关文件位于 deploy 目录：

- docs：需求 / 设计 / 计划文档
- server：Go frps / frpc 二开（fork fatedier/frp）
- panel：面板 + 官网（FastAPI）
  - app：主应用（API / 模型 / 任务）
  - web：面板前端（Vue3 + Naive UI）
  - templates：官网 Jinja2 模板
- client：Electron 桌面客户端（Windows）
- emergency：应急服务（独立轻量进程）
- deploy：Docker Compose + 配置（.env.example 等）

### 5.2 部署流程

1. 获取项目代码（Monorepo，包含 server、panel、client、emergency、deploy 各目录）
2. 构建面板前端：Vue3 + Naive UI 前端构建为静态文件
3. 配置环境变量：复制 deploy 目录 .env.example 为 .env，按部署环境填写
4. 启动服务：在 deploy 目录执行 docker compose up，拉起 4 容器全套服务
5. 配置 HTTPS 反向代理：面板与官网监听 8000 端口，由外部反向代理将公网 HTTPS 请求转发到 8000
6. 上传 HTTPS 证书：手动上传证书并配置（不支持自动签发）

### 5.3 HTTPS 反代与证书说明

- 8000 端口承载面板 + 官网，对外通过 HTTPS 反向代理访问
- HTTPS 证书采用手动上传方式配置，不支持自动签发，上线前需准备正式域名证书

## 6. 免费域名说明

- 开发阶段使用占位域名 weave.test
- 用户申请子域名后，面板校验占用情况，生成 xxx.weave.test（占位域名），frps 按域名路由
- 上线前必须将占位域名替换为正式域名，并为正式域名配置泛解析

## 7. 应急服务

应急服务是独立的逃生通道，与面板完全解耦，保证面板、数据库、Redis 全部故障时仍可响应。

### 7.1 设计要点

- 独立进程 / 容器，与面板完全解耦，面板 / 数据库 / Redis 全挂也能响应
- 独立端口 9001，仅内网 / VPN 访问
- 预共享强随机应急密钥鉴权
- 零依赖（标准库实现），不连接数据库 / Redis
- 每次操作写本地审计日志

### 7.2 接口清单

- GET /health：存活检查
- GET /status：系统状态（CPU / 内存 / 磁盘 / 容器状态）
- GET /logs?service=panel&lines=200：拉取服务日志
- GET /data?type=users|tunnels|nodes：直连 SQLite 拉取只读数据
- POST /restart?service=panel|frps|redis|all：重启服务
- POST /stop?service=all：停止服务
- POST /start?service=panel|frps：启动服务
- POST /reboot：重启服务器
- POST /exec?cmd=...：受限白名单命令执行（可选）

### 7.3 安全防护

- 强随机密钥（>= 32 位），存放于独立配置文件
- 可选 IP 白名单
- 连续失败 5 次锁定 10 分钟
- 危险操作（reboot）需二次确认参数
- 应急 API 独立状态码约定：200 成功 / 401 密钥错误 / 423 已锁定 / 400 参数错误

## 8. 运维指引

### 8.1 日志查看

- 通过应急服务拉取服务日志：GET /logs?service=panel&lines=200
- 管理后台提供操作日志与运行日志（/api/admin/logs）

### 8.2 数据备份

- 数据库为 SQLite，持久化于 weave-panel 挂载的数据卷
- 备份 weave-panel 的 sqlite 数据卷即可完成数据备份
- 在线状态与实时流量缓存于 Redis 不入库，无需备份；历史流量按日聚合入 traffic_stats

### 8.3 升级方式

- 服务由 Docker Compose 编排（4 容器），升级时更新对应服务镜像并重建容器

### 8.4 故障排查

- frps 掉线：面板心跳检测超过 60s 无心跳即标记节点离线，不阻塞其他功能
- SQLite 锁冲突：通过 WAL + busy_timeout 缓解，写操作自动重试
- SMTP 失败：邮件发送采用内存队列，失败重试 3 次
- 客户端网络中断：Electron 客户端指数退避重连

## 9. 测试与验收

### 9.1 端到端验收

使用 docker compose 起全套服务后，按以下流程验收：

1. 注册：用户注册账号
2. 建隧道：在面板创建隧道
3. 客户端连接：Electron 客户端连接 frps 建立隧道
4. 公网访问验证：通过公网地址访问隧道服务

### 9.2 应急演练

模拟面板崩溃场景，验证应急 API 全流程可用，确认面板、数据库、Redis 全部故障时应急服务仍可响应并执行操作。

### 9.3 性能冒烟

500 隧道在下面板响应正常、Redis 状态刷新正常。
