## 阅读顺序

1. 先读需求收集，了解项目的来龙去脉与每轮决策结论
2. 再读设计文档，掌握系统整体架构与技术细节
3. 后读项目目标，明确项目要达成的目标与验收标准
4. 按角色选择深入阅读：
   - 开发者：API 文档、开发文档、部署文档、测试报告
   - 运维人员：部署文档、API 文档（应急 API 章节）
   - 普通用户：用户手册

## 文档演进守则

本目录文档分为源文档与派生文档两层，任何新增或修订都必须遵守以下规则，防止文档间产生分歧：

- 源文档（需求收集、设计文档）记录决策与设计事实，是唯一权威依据
- 派生文档（项目目标、API 文档、部署文档、用户手册）必须严格取材于源文档，不编造源文档中不存在的细节
- 修订派生文档时，先核对源文档原文，逐条保持一致；如发现需要新增事实，应先回到源文档补充结论，再同步派生文档
- 涉及套餐数值、端口、业务码、接口路径、时间阈值等关键参数时，所有文档必须使用同一数值，修订一处需同步检查其余文档
- 新增文档须在本索引登记路径、类型与适用角色，并纳入阅读顺序
